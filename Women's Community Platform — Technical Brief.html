Women's Community Platform — Technical Brief

Version 1.0 · Scope: MVP + Phase 2 roadmap Member registration · Business promotion · Community connections

1. Purpose & Vision

A premium, women-focused community platform that combines a professional network, business (SME) directory, buy & sell marketplace and events platform in one simple product. Members register, are verified by an admin, and publish profiles, business listings, items and events. All public content passes through an admin review workflow before going live. Visitors browse, enquire, buy/contact and register for events.

Success criteria

  • A new member can register and submit a profile in under 5 minutes.
  • Admin can review any submission in under 2 minutes.
  • Public pages load in under 2.5s (LCP) on mobile.
  • Fully usable on mobile (majority of expected traffic).

2. User Roles & Permissions

Role Description Key permissions
Visitor Anonymous public user Browse directories, view listings/events, send enquiries, register for events, contact/buy
Member Approved registered woman Manage own profile, business, items, events (submit for review); dashboard; connect with members
Pending member Registered, awaiting approval Login, edit profile, view status; cannot publish
Admin Platform manager Approve/reject members and content, feature listings, manage users/events, view reports
Super admin Technical owner Admin rights + settings, admin accounts, audit log, data export

3. Core Workflows

3.1 Membership

  1. New member: registers → verifies email → completes profile → status PENDING.
  2. Existing member: admin uploads/creates member (CSV import or manual) → system sends invitation link (signed, expiring token) → member accepts, sets password, updates profile → PENDING (or auto-APPROVED if admin flags pre-verified).
  3. Admin approval: reviews details → APPROVED (welcome email, dashboard unlocked) or REJECTED (with reason, member can edit and resubmit).

3.2 Content lifecycle (profiles, SME listings, items, events)

DRAFT → SUBMITTED → IN_REVIEW → APPROVED → PUBLISHED
                        │
                        └→ CHANGES_REQUESTED → (member revises) → SUBMITTED
                        └→ REJECTED (final, with reason)
PUBLISHED → ARCHIVED / EXPIRED (items after N days; events after end date)
  • Every state change is logged (who, when, comment) in a review history.
  • Edits to already-published content re-enter review (configurable: minor edits auto-publish).
  • Email + in-app notification on every status change.

3.3 Visitor journey

Browse → search/filter → view detail → Enquire (form, sent to owner + logged), Buy (contact or checkout, see 4.5) or Register for event.

4. Functional Requirements

4.1 Authentication & Registration

  • Email + password, plus optional Google sign-in. Email verification mandatory.
  • Password reset, session management, rate-limited login, optional 2FA for admins.
  • Registration fields: full name, email, phone, city/country, short bio, photo, industry/interests, social links, consent to terms and directory visibility.

4.2 Member Profile & Public Directory

  • Public profile: photo, name, headline, bio, location, skills/interests, links, linked business.
  • Visibility controls (public / members-only / hidden fields such as phone).
  • Directory: search by name, keyword, location, industry; filters; pagination; "Featured" badge.
  • Member-to-member connect/message (Phase 1: contact request via platform email relay; Phase 2: in-app messaging).

4.3 SME / Business Directory

  • Business profile: name, logo, banner, category, description, products/services (name, description, images, price optional), contact details, website, social links, opening hours, location/map.
  • Categories and tags managed by admin.
  • Enquiry form per business; enquiries visible in member dashboard.
  • Featured SMEs shown on home page and top of category results.

4.4 Events

  • Event fields: title, type (cultural / corporate / property / webinar / other), description, banner, date/time, timezone, venue or online link, capacity, price (free/paid), organiser, tags.
  • Members submit events (review workflow); admin can create events directly.
  • Public event calendar/list, filters by type/date/location, event detail page.
  • Registration: name, email, phone, custom questions, ticket quantity; confirmation email with calendar (.ics) file; capacity and waitlist handling; attendee list export (CSV) for organiser/admin.

4.4.1 Home-page "See What's Happening" Feed

Inspired by the event feed on wlnarkansas.org: a compact, visual stack of upcoming events that shows visitors the community is active.

Element Specification
Heading "See What's Happening" with a one-line intro
Data source Only published events with ends_at in the future, sorted by start date; admin-pinned events (is_pinned_home) appear first
Card count 3 cards: single column on mobile, 3-column grid on desktop; configurable in admin settings
Card content 16:9 banner image, event-type chip (Cultural / Corporate / Property / Webinar / Other), title, date, time and timezone, location or "Online", Free/Paid tag, "X spots left" when capacity is set, optional sponsor line/logo
Actions "View event" button on each card (or "Register" when registration is open); "See all events" button below the feed linking to the full events directory
Banner handling Uploads auto-cropped to 16:9 with focal-point control; branded text fallback (event type + date on lavender/teal background) when no image is supplied
Empty state "No upcoming events yet. Share yours with the community." with a button to submit an event (members) or join (visitors)
Performance Server-rendered, cached (ISR, revalidated on event publish/update), lazy-loaded images with reserved aspect ratio to avoid layout shift
Accessibility Each card is one focusable link region, meaningful alt text from the event title, visible date/time as text (never only inside the image)

Acceptance: an event appears in the feed within one minute of admin approval, disappears automatically after it ends, and pinned events always appear before unpinned ones.

4.5 Buy & Sell Marketplace

  • Listing: title, category (used items, moving-out sales, other), condition, price, images (up to 8), location, description, status (AVAILABLE, RESERVED, SOLD), auto-expiry (default 60 days, renewable).
  • Buyer actions: Contact seller (relay form, no raw contact exposed unless seller allows). Saved items (logged-in members).
  • Payments: MVP is contact-based (peer-to-peer, no platform payments). Phase 2: online checkout via Stripe/Razorpay for SME products and paid events.
  • Report-listing button feeding admin moderation queue.

4.6 Member Dashboard

  • Overview: profile completeness, status of each submission, notifications.
  • Tabs: My Profile · My Business · My Listings (products/services) · Buy & Sell · My Events · Enquiries · Registrations · Saved.
  • Clear status chips (Draft, In review, Changes needed, Live) with admin comments and a one-click Revise & resubmit.

4.7 Admin Dashboard

  • Approvals queue: members and content, filterable by type/status/age; side-by-side view, approve / request changes / reject with templated reasons.
  • Featured management: drag-to-order featured members/SMEs, schedule start/end dates; pin events to the home-page "See What's Happening" feed.
  • Users: search, suspend, reactivate, change role, import existing members (CSV), resend invitation.
  • Events: create/edit, view registrations, export.
  • Moderation: reported listings, spam enquiries.
  • Reports: new registrations, approval turnaround, active listings by type, enquiries, event registrations, top categories; CSV export.
  • Settings: categories, email templates, terms, review rules, audit log.

4.8 Notifications

Transactional email (verification, invitation, approvals, changes requested, enquiry received, event confirmation/reminder) plus in-app bell. Admin digest of pending items.

4.9 Search

Global search across members, businesses, items, events. MVP: PostgreSQL full-text + trigram; Phase 2: Meilisearch/Algolia if volume demands.

6. Recommended Architecture & Tech Stack

Layer Recommendation
Frontend Next.js (App Router) + TypeScript, Tailwind CSS, shadcn/ui (Radix), React Hook Form + Zod
Backend Next.js server actions / route handlers (or NestJS API if a separate mobile app is planned)
Database PostgreSQL with Prisma ORM
Auth Auth.js (NextAuth) or Clerk; RBAC middleware; signed invitation tokens
Storage S3-compatible bucket + CDN; image optimisation (Next Image / Cloudinary)
Email Resend / SendGrid / Amazon SES with React Email templates
Payments (Phase 2) Stripe and/or Razorpay
Background jobs BullMQ/Redis or Inngest (email queue, expiry jobs, reminders)
Search PostgreSQL FTS → Meilisearch later
Hosting Vercel (app) + managed Postgres (Neon/Supabase/RDS); or Docker on AWS/DigitalOcean
Monitoring Sentry, uptime checks, PostHog/GA4 analytics
CI/CD GitHub Actions: lint, type-check, tests, preview deploys, staged rollout

Architecture: monolithic modular app (modules: auth, members, businesses, marketplace, events, review, notifications, admin, reports) so it can be split later.

Reference style: clean, elegant, women-focused; rounded cards, simple line icons, generous whitespace, calm hierarchy (inspired by the supplied workflow diagram, WLN, National Women's Collaborative and Chief).

UX principles

  • Home page: hero with clear "Become a member" CTA → stats → "See What's Happening" event feed (see 4.4.1) → featured SMEs → marketplace highlights → member stories → newsletter. The event feed sits directly under the hero/stats so activity is visible without scrolling far.
  • Simple top navigation: Members · Businesses · Marketplace · Events · About · Join / Login.
  • Status colour language consistent across dashboards: lavender = draft, teal = approved/live, blush = changes needed.
  • Mobile-first, cards stack cleanly; sticky bottom action bar on mobile dashboard.
  • Accessibility: WCAG 2.2 AA (contrast, focus states, keyboard nav, alt text, reduced motion).

10. Non-Functional Requirements

  • Security: HTTPS everywhere, OWASP Top 10 controls, hashed passwords (Argon2/bcrypt), CSRF/XSS protection, file-type and size validation, virus scan on uploads, RBAC, audit logging.
  • Privacy: consent capture, field-level visibility, data export and deletion on request (GDPR-style), no exposure of contact details without permission.
  • Performance: image optimisation, CDN, caching/ISR for public pages, DB indexing on slug/status/category/date.
  • Scalability: target 10k members, 5k active listings without re-architecture.
  • SEO: server-rendered pages, clean slugs, meta/OG tags, sitemap.xml, structured data (Organization, LocalBusiness, Event, Product).
  • Reliability: daily DB backups with restore test, staging environment, error monitoring.
  • Anti-abuse: CAPTCHA (hCaptcha/Turnstile) on forms, rate limits, report flow, profanity/spam filters.
  • Internationalisation-ready: timezone-aware events, currency configuration, i18n structure for future languages.

12. Acceptance Criteria (MVP)

  1. New and invited members can register/activate; admin can approve or reject with reason.
  2. Approved members can create profile, business with offerings, market items and events.
  3. No content is public until approved; changes-requested content can be revised and resubmitted; history is recorded.
  4. Public can browse, search and filter all four directories; enquiries and event registrations are delivered and stored.
  5. Admin can feature members/SMEs, manage users/events, and view reports.
  6. Emails and notifications fire for all workflow transitions.
  7. Meets performance, accessibility and security targets in Section 10.

13. Open Questions for Stakeholders

  1. Is membership free, paid, or both? Are there membership tiers?
  2. Should online payments be included at launch, or contact-based only?
  3. Countries/currencies/languages to support?
  4. Who verifies members and what evidence is required (ID, business registration, referral)?
  5. Should minor edits to published content need re-approval?
  6. Number of existing members to import, and their data format?
  7. Branding assets available (logo, fonts, photography), and domain/hosting preferences?
